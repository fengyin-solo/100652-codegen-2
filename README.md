# 城市供水厂制水运行与供水调度管理平台

面向水厂台账、取水泵组、混凝加药、沉淀池运行、滤池反冲洗、消毒加氯、清水池调蓄、出厂水质检测、供水调度指令、管网压力监测、二次供水泵房、水表抄见、爆管抢修、原水监测、阀门井巡检、药剂领用、设备维护与值班交接的一体化城市供水制水调度工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

### 停水通知与影响范围（`wateroutage`）

城东片区一停水客服电话就打爆，这个模块围绕「谁受影响、停多久、走哪条渠道」组织，业务规则比通用台账
复杂，因此有独立的数据层（`src/data/water-outage.ts` / `water-store.ts`，localStorage 键
`waterworks-ops:water-outage`）和独立服务 `src/api/water-outage-service.ts`：

- 每次停水开一张通知，影响小区**逐行排列**：小区名称、小区级停水起止、该小区的通知渠道，一眼看出
  哪几个小区停多久、走哪条渠道；小区级时段与通知级时段不一致也支持（如某小区只停半天）。
- **影响小区为空的通知不许发布**；同一停水编号不许重复发布（新建/编辑草稿时即拦截）。
- 草稿可反复改停水时段，每次改动版本号 +1，**以最后一版为准**。
- 状态不许跳级，只能 **草稿 → 已发布 → 已结束**；已发布后影响范围、停水时段全部冻结，
  **只许追加补充说明**（带时间与操作人，历史不可改），不许把影响小区改小。
- 发布动作严格按顺序执行：**① 影响范围落库（快照）→ ② 通知渠道下发 → ③ 驱动客服诉求清单重排**。
  渠道故障时通知仍是草稿、落库保留，页面出现「重试发布」；重试复用已落库快照并累计尝试次数。
  列表上方有「模拟渠道故障/恢复」开关可演示这条路径。
- 列表页与详情页共用 service 里的 `formatWindow` / `formatDuration`，读到的停水时段口径一致。
- 客服诉求清单在 `/wateroutage/tickets`：发布命中影响小区的**未办结**诉求按发布序号置顶（已办结沉底），
  并记录关联停水编号与重排原因，可在详情页点编号跳回对应通知。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 停水通知模块例外：页面走 `src/api/water-outage-service.ts`，数据持久化在
  `waterworks-ops:water-outage`，不与通用台账的 `waterworks-ops:entries` 混库。
- 想回到初始数据：清掉浏览器里 `waterworks-ops:entries` 这一项，或调用 `resetModule(模块)`；
  停水通知模块可在列表页点「恢复示例数据」（或清掉 `waterworks-ops:water-outage`）。
